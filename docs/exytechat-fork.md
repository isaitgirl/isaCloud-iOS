# Fork do ExyteChat

O chat do app (balões, lista de mensagens) é a biblioteca ExyteChat. O Monal usa o fork dele, `monal-im/ExyteChat`; o isaCloud usa um fork desse fork, para poder mudar o que a biblioteca desenha sem contornos no app.

```
exyte/Chat  →  monal-im/ExyteChat (main)  →  isaitgirl/ExyteChat (branch isaCloud)
```

- Repositório: `https://github.com/isaitgirl/ExyteChat`, branch **`isaCloud`** (é a única branch que o projeto usa; nunca a `main`, que acompanha o `monal-im/ExyteChat`).
- Revisão em uso: **`8789fe3`** (30/10/2026, `setMessageTimeFont`: a fonte da hora pela API pública, PR 10 do Jejê); antes, **`078475d`** (versiona o `Package.resolved` do fork; logo antes, `1fcf83d`: o status "enviando" mostra o spinner no lugar do relógio, PR 9 do Jejê). Antes disso, **`371276e`** (28/10/2026, a hora das mensagens só com foto ou vídeo fica embaixo do balão, fora da imagem; antes, em 27/10/2026: o menu da mensagem usa a altura da janela e não corta as ações com o teclado aberto; antes: o gesto de responder deixa a lista rolar pelo balão no iOS 27, citações aninhadas e gesto de responder mais fluido, responder puxando o balão para a direita e, em 26/10/2026, componentes nativos na modal, emojis que quebram linha e reações no rodapé do balão como opção desligada por padrão; os PRs do fork foram mesclados com rebase e com squash, por isso o SHA é o do `isaCloud` do fork, e não o dos commits dos PRs). Ela fica fixada em `Monal/Monal.xcworkspace/xcshareddata/swiftpm/Package.resolved`; o `project.pbxproj` só diz `branch = isaCloud`. **Depois de cada commit novo no fork é preciso atualizar essa revisão** (e fazer o push antes), senão o TestFlight compila a versão antiga.
- Clone de trabalho: `~/projects/swift/ExyteChat`, com os remotos `origin` (nosso fork) e `upstream` (`monal-im/ExyteChat`).
- O projeto referencia o pacote em `Monal/Monal.xcodeproj/project.pbxproj` (`repositoryURL` e `branch`) e `Monal.xcworkspace`/`Package.resolved` fixa a revisão.

O motivo da decisão (e as alternativas descartadas) está em `docs/decisoes.md`.

## O que o fork muda (só isto)

Cada mudança é pequena, comentada com "isaCloud:" no código e vive num commit próprio, para o rebase ser fácil.

1. **Ícones de status maiores** (`MessageView.swift`): `statusViewWidth` de 10 para 16 pt, mantendo o ícone alinhado pela base do balão. Esse valor também entra nas contas de largura do balão.
2. **Citação com uma barra só** (`Extensions/AttributedString+Quote.swift`, `MessageTextView.swift`, `MessageView.swift`): o app marca o texto citado com o atributo `quote` (`texto.quote = true`) e o balão desenha cada citação como um bloco com uma barra vertical contínua à esquerda. Mensagens com citação sempre põem a hora embaixo do texto. **Citações aninhadas (27/10/2026, como no Conversations):** o atributo `quoteDepth` (1, 2, 3...) diz a profundidade da citação (`quote = true` continua valendo, como profundidade 1); o texto vira uma árvore (`textTree`) e uma citação de profundidade 2 é desenhada dentro da de profundidade 1, com a barra de fora cobrindo tudo e a de dentro só as linhas dela. Testes em `Tests/ExyteChatTests/QuoteTreeTests.swift`.
3. **Menu da mensagem abre mais cedo** (`Views/UIList.swift`): o toque longo passa de 0,5 s (padrão do SwiftUI, sentido como ~0,6 s na lista) para `minimumDuration: 0.3`. A animação do menu não precisa de mudança na biblioteca: o app chama `.messageMenuAnimationDuration(0.15)` (padrão da biblioteca: 0,3 s) em `ChatView.swift`. Os GIFs, que o app desenha por conta própria, usam os mesmos 0,3 s em `GifMessageBubble`.
4. **Modal de quem reagiu** (`Model/ReactionGroup.swift`, `Views/MessageView/ReactionDetailsSheet.swift`, `MessageReactionView.swift`, `ChatViewModel.swift`, `ChatView.swift`, `ChatBuilderParameters.swift`, `ChatMessageView.swift`, `ChatLocalization.swift`): as reações do balão são agrupadas por emoji (um círculo por emoji, com selo de contagem quando mais de uma pessoa reagiu) e tocar nelas abre uma modal com uma linha por pessoa (emojis dela à direita, em faixa rolável; ordem alfabética), com filtro por emoji. A linha "Você" é sempre a primeira: cada emoji dela é um botão que remove a reação e um "+" abre o teclado de emojis do sistema para adicionar (`Views/MessageView/EmojiKeyboardField.swift`, um campo de texto invisível que pede o teclado de emojis; `Model/ReactionPeople.swift` agrupa por pessoa). Com a opção desligada (padrão da biblioteca, e o que o app usa quando a preferência "Reações acima das mensagens" está ligada) cada reação é uma bolinha sobre o canto do balão e, nos balões de outras pessoas, o selo de contagem fica por cima do balão vizinho. Balões próprios do app (como o dos GIFs) abrem a mesma modal por `MessageBuilderParameters.showReactionDetailsClosure`. No app, `shouldShowOverviewFor` devolve `false`, porque a modal substitui a lista que aparecia no topo do toque longo. Testes em `Tests/ExyteChatTests/ReactionGroupTests.swift`. **Componentes nativos e rodapé (26/10/2026):** com a opção `ChatView.reactionsBelowBubble(true)` (o app liga por padrão; a preferência "Reações acima das mensagens", em Configurações → Interface do Usuário → Aparência, desligada por padrão, volta ao modo antigo) as reações do balão saem de cima dele e ficam no rodapé, centralizadas, em cápsulas nativas (`Button` com `.bordered` e `.capsule`, emoji e número juntos; no balão rosa as cápsulas são brancas e sólidas; passando de 5 emojis, o "+N" é mais uma cápsula). Na modal, os chips, o "+" e os emojis da linha "Você" são `Toggle` em estilo botão e `Button` bordered, e a lista é uma `List`, e os emojis de cada pessoa quebram a linha em quantas linhas precisar, alinhados à direita (`FlowLayout`, um `Layout` próprio: o SwiftUI não tem um HStack que quebra linha). O código dos balões redondos antigos (`reactionsView`, `overflowBubbleView`, `ReactionBubble`) continua, é o modo da preferência "Reações acima das mensagens".
5. **Responder puxando o balão** (`Views/MessageView/ChatMessageView.swift`, `Views/PublicAPI.swift`, `ChatViewModel.swift`, `ChatCustomizationParameters.swift`, `ChatView.swift`): puxar um balão para a direita responde a ele. O balão acompanha o dedo (mais devagar depois de 64 pt, até 96 pt), uma seta de resposta aparece atrás e fica preenchida quando soltar já responde (com um toque de vibração), e ao soltar o balão volta com uma mola (o bounce) e o campo de texto ganha o foco. Só conta o arrasto que começa na horizontal e longe da borda esquerda, para não brigar com a rolagem nem com o gesto de voltar. API: `.onSwipeToReply(activeFor:onReply:)`; no app, `onReply` faz a mesma citação do "Responder" do menu. Vale para o balão padrão e para os balões próprios do app (o gesto fica na célula, não no balão). **Fluidez (27/10/2026):** o estado do arrasto não pode ser `@State` da `ChatMessageView`, porque ela monta a mensagem inteira (o `messageBuilder` do app e o balão) e era montada de novo a cada quadro; ele vive em `PullToReplyState` e o gesto, o offset e a seta em `PullToReplyContainer`, que é a única view que o lê. A vibração é preparada no começo do gesto e a resposta (citação e teclado) vem 0,35 s depois de soltar, quando o bounce termina. **Rolagem (27/10/2026):** no iOS 18+ o gesto é um pan do UIKit (`SidewaysPanGesture`) que só começa para a direita, para a lista voltar a rolar quando o dedo começa no balão no iOS 27; no iOS 26+ o "voltar" de tela cheia espera esse pan falhar; iOS 17 mantém o `DragGesture` (PR `isaitgirl/ExyteChat#6`).
6. **Reações no rodapé do balão** (`MessageReactionView.swift`, `MessageView.swift`, `ChatCustomizationParameters.swift`, `PublicAPI.swift`): ver o item 4; é uma opção, `.reactionsBelowBubble(_:)`, desligada na biblioteca, e o app liga por padrão.
7. **Menu da mensagem com o teclado aberto** (`Views/MessageView/MessageMenu/MessageMenu.swift`, `chatViewFrame`): a altura do menu é `max(chatSize.height, windowSize().height)`. Com o teclado levantado, `chatSize.height` é só a lista acima dele, e o menu era montado nesse espaço, virava rolagem e cortava as ações (PR `isaitgirl/ExyteChat#7`, 27/10/2026). Se o upstream trouxer algo parecido, descartar o nosso commit.
8. **Hora de foto e vídeo embaixo do balão** (`Views/MessageView/MessageView.swift`, `MessageTimeView.swift`; PR 8, 28/10/2026): em mensagem com anexo e sem texto (`timeBelowMedia`) a cápsula escura com a hora sai de dentro da imagem (`attachmentsView(_:showTimeInside:)`) e a hora vai embaixo do balão (`MessageTimeBelowView`: cadeado se criptografada, cor secundária), do lado da mensagem, como o rodapé dos GIFs do app. A prévia de uma resposta (`replyBubbleView`) e a mensagem com legenda não mudam.
9. **Spinner de envio** (`Views/MessageView/MessageStatusView.swift`, 28/10/2026): o status `.sending` mostra um `ProgressView` pequeno em vez do relógio parado, para uma mensagem que demora a sair mostrar que está trabalhando. Vale também para a mensagem que já foi gravada e ainda não foi ao servidor. O app mostra a mensagem logo ao enviar, com esse status (ver `docs/decisoes.md`).
10. **Fonte da hora pela API pública** (`Views/PublicAPI.swift`, 30/10/2026): `setMessageTimeFont(_:)`, ao lado de `setMessageFont(_:)`. O fork já usava `timeFont` para a hora; falta só o setter, para o app escalar a hora junto com o texto ("Tamanho do texto nas conversas", ver `docs/decisoes.md`). Commit próprio, sem mudança de comportamento para quem não chama.

## Fluxo de branches e PRs

- Toda mudança, no app e na biblioteca, nasce em um branch novo criado **a partir de `isaCloud`** (por exemplo `feature/reaction-details-sheet`) e volta por **PR do branch novo para `isaCloud`** do mesmo repositório. Nunca para `develop` (app) nem para `monal-im`.
- Todo PR tem a `isaitgirl` como revisora e responsável e traz **prints de antes e depois** das mudanças visíveis, feitos só com dados de teste (contas e conversas de teste, nunca conversas reais, porque as imagens ficam públicas). As capturas seguem a convenção de `CLAUDE.md` e entram no branch do PR (a pasta `docs/screenshots/` está no `.gitignore`, então use `git add -f`).
- Mudança que depende da biblioteca tem um PR par em cada repositório. O PR do app só pode ser mesclado depois do PR do ExyteChat, porque o app usa o branch `isaCloud` da biblioteca.
- **Sem branches soltas:** depois que o PR é mesclado e o que ele trouxe está na `isaCloud` (do app e do ExyteChat), o branch do PR é apagado, no GitHub e na cópia local, **sempre depois de pedir a confirmação da Isadora** (lista das branches e do que cada PR trouxe); os clones ficam na `isaCloud`. Branches que já têm PR mesclado com rebase (o SHA muda) aparecem como "não mesclados" no Git: confira com `git cherry isaCloud <branch>` (nenhuma linha com `+` quer dizer que está tudo na `isaCloud`).
- Quem não tem permissão de escrita no `isaitgirl/ExyteChat` trabalha num fork próprio e abre o PR do fork para o `isaCloud` dela.
- Prints de reações e outros emojis: só em simulador sem o defeito de emoji (ver `docs/troubleshooting.md`, iOS 26.4 ou mais novo, ou 27.x).

## Como acompanhar o Monal e o ExyteChat

```bash
cd ~/projects/swift/ExyteChat
git fetch upstream
git checkout isaCloud
git rebase upstream/main      # ou: git merge upstream/main
# resolver conflitos (as nossas mudanças estão em poucos trechos de MessageView.swift e MessageTextView.swift)
git push --force-with-lease origin isaCloud     # só se usou rebase
```

Depois, no projeto isaCloud: atualizar a revisão fixada (Xcode → File → Packages → Update to Latest, ou apagar a entrada em `Package.resolved` e resolver), compilar nos simuladores iOS 18 e iOS 27 e conferir um chat com citação, GIF, foto e mensagens com os quatro ícones de status.

Se o Monal fixar o `monal-im/ExyteChat` numa versão nova, vale conferir em `Package.resolved` se a `develop` do Monal exige uma revisão mais nova que a do nosso fork antes de fazer o merge com o Monal.

## Se um dia o Monal ou o ExyteChat trouxerem o mesmo recurso

Ícones e citação com barra são candidatos a contribuição. Se o upstream implementar, basta descartar o nosso commit correspondente no rebase e adaptar o app.
